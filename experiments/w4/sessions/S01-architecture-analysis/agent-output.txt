  ## 3. Hidden Coupling and Import-Time / Global-State Behaviour

  1. Import-Time Environment Variable Parsing (packages/shared/config.ts):
      • serverConfigSchema.parse(process.env) is evaluated immediately upon module import (config.ts` L592-593).
      • Strict boolean validation helper stringBool explicitly rejects values other than "true" or "false". Standard runner flags like NO_COLOR=1 throw an uncaught ZodError at
      import time, crashing Vitest module collection.
  2. Synchronous SQLite File Opening on Import (packages/db/drizzle.ts):
      • openSqliteDatabase(dbConfig.dbCredentials.url, ...) runs immediately when packages/db is imported (drizzle.ts` L15-18), locking ./db.db. Test suites must import
      getInMemoryDB(true) instead.
  3. Global Plugin Loader State on globalThis (packages/shared-server/src/plugins.ts):
      • Global variable globalThis.__karakeep_plugins_loader_state__ controls plugin registration (plugins.ts` L5-14). Registration order determines the active provider
      (assetstore-s3 overrides filesystem, ratelimit-redis overrides memory).
  4. NextAuth Session Cookie Encryption Coupling:
      • Session cookies are encrypted/signed with NextAuth v4's proprietary HKDF + AES-GCM logic using NEXTAUTH_SECRET. A Python service cannot read session cookies directly
      without replicating this cryptographic pipeline or relying on a reverse proxy.
  5. REST Route Dependence on In-Process tRPC Caller:
      • In packages/api/middlewares/auth.ts` L35, c.set("api", createCaller(c.get("ctx"))) injects the tRPC caller. Every REST handler delegates to tRPC. packages/api provides
      no standalone API layer.
  6. Asynchronous Side Effect to queue.db via liteque:
      • Updating, deleting, or merging tags triggers triggerSearchReindex(bookmarkId) (packages/trpc/models/tags.ts` L291, L329, L369). This pushes jobs into SQLite database
      queue.db. A Python backend writing to db.db must also write valid liteque payloads to queue.db to prevent Meilisearch indexes from desynchronizing.

  ## 4. Evaluation of Baseline Investigation (Errors & Omissions)
  1. Undercounted Baseline Tests:
      • The baseline reported ~79 tests in packages/trpc. However, packages/trpc/routers/tags.test.ts alone has 30 passing tests. Across the 21 test files, actual test count is
      much higher.
  2. Omission of tRPC vs REST Functional Disparity on Tags:
      • The baseline notes that some tag operations exist in tRPC but not in REST, but did not inventory them:
          • Tag.merge is implemented in tRPC (tags.merge) and used by apps/cli and apps/web, but is completely missing from packages/api/routes/tags.ts and OpenAPI.
          • Tag.deleteUnused is in tRPC and used by apps/web (AllTagsView.tsx), but is completely missing from packages/api/routes/tags.ts and OpenAPI.
      • If the Python migration only reproduces the existing REST route file, merge and deleteUnused will remain unmigrated.
  3. Client Protocol Reality:
      • The baseline implies multiple clients can test the REST endpoint. In reality, apps/mcp is the only client that calls the REST /v1/tags API. Web, Mobile, Browser
      Extension, and CLI all communicate with /api/trpc/tags.*. Client verification of a Python REST service requires either testing via MCP/SDK or adapting a client.
  4. Missing Scope Middleware in TypeScript REST Layer:
      • packages/api/routes/tags.ts does not attach apiKeyScopeMiddleware. Scope enforcement was entirely delegated to tRPC's createScopedAuthedProcedure("tags"). The Python
      REST implementation must implement API key scope checks explicitly.
